# T-008: Sequential Download Mode & Concurrency Limiting

* **Milestone**: 2 (Queue & Scheduler)
* **Dependencies**: `T-007`
* **Status**: Completed
* **Scope**:
  * Implement sequential chunk download mode (`--sequential` in `internal/engine/options.go` and `internal/engine/worker.go`), ensuring chunks are fetched strictly in monotonic order ($0, 1, 2, \dots, N-1$) to allow progressive media streaming and playback during download.
  * Implement concurrency limiter in `internal/queue/semaphore.go` bounding active concurrent network requests across tasks and chunk workers.
  * Wire sequential mode and concurrency limiting into `Coordinator.DownloadWithOptions()`.
* **Deliverables**:
  * `internal/engine/options.go`, `internal/queue/semaphore.go`, `internal/engine/worker.go`
  * `internal/engine/sequential_test.go`, `internal/queue/semaphore_test.go`
  * `examples/sequential_demo/main.go`
* **Testable Outcome**:
  * Executing a partitioned download with `Sequential: true` verifies that chunks are requested and written strictly in head-to-tail order ($0 \to 1 \to 2 \to 3$), producing a bit-for-bit identical file while enforcing semaphore capacity limits.
  * Verified passing via `go test -v -race ./...` and `make test`.
