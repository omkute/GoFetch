# T-008: Sequential Download Mode & Concurrency Limiting

* **Milestone**: 2 (Queue & Scheduler)
* **Dependencies**: `T-007`
* **Status**: Completed
* **Scope**:
  * Implement global concurrency limiting via `--max-concurrent` / `-j` (default: 3) on the root and daemon commands, applied to `queue.NewScheduler` and to the `concurrency.max_concurrent_downloads` configuration value (flag overrides config).
  * Implement task-level strict sequential mode: `--sequential` or `-j 1` dispatches exactly one download at a time in strict submission (FIFO) order, ignoring priority.
  * Preserve the per-file head-to-tail chunk ordering capability under the distinct `--chunk-sequential` flag, wired to `DownloadOptions.Sequential`.
  * Implement the concurrency limiter via token semaphore in `internal/queue/semaphore.go`.
* **Deliverables**:
  * `internal/queue/scheduler.go`, `internal/queue/priority_heap.go`, `internal/engine/options.go`, `cmd/gofetch/root.go`, `cmd/gofetch/daemon.go`, `config/config.go`
  * `internal/queue/scheduler_fifo_test.go`, `cmd/gofetch/concurrency_test.go`, `tests/integration/queue_order_test.go`
  * Canonical semantics documented in `docs/PRODUCT.md`, `tasks/BACKLOG.md`, and `README.md`.
* **Testable Outcome**:
  * Queuing 5 distinct download URLs in `-j 1` / `--sequential` mode verifies that exactly one download runs at any instant and that tasks complete strictly in submitted sequence.
  * `--chunk-sequential` still requests and writes the chunks of a single partitioned file strictly in head-to-tail order ($0 \to 1 \to 2 \to 3$), producing a bit-for-bit identical file.
  * Verified passing via `make test` (`go test -v -race ./...`) and `make lint`.
