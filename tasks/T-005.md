# T-005: Resumability, Checkpoints & Transient Error Retry

* **Milestone**: 1 (Engine Core)
* **Dependencies**: `T-004`
* **Status**: Completed
* **Scope**:
  * Implement checkpoint state persistence in `internal/state/bbolt.go` and `internal/state/checkpoint.go` using `go.etcd.io/bbolt` to record job metadata and per-chunk download offsets (`Current`).
  * Implement exponential backoff retry loop with full jitter in `internal/engine/retry.go` for transient network errors (dropped connections, 429, 503, connection resets).
  * Enable resume capability in `Coordinator`: check checkpoint on startup, open existing `.gofetch.part` file, skip already finished chunks, and resume in-flight chunks strictly from their last saved byte offset.
* **Deliverables**:
  * `internal/state/bbolt.go`, `internal/state/checkpoint.go`, `internal/engine/retry.go`, `internal/engine/checkpoint.go`
  * `internal/state/checkpoint_test.go`, `internal/engine/retry_test.go`, `internal/engine/resume_test.go`
  * `examples/resume_download/main.go`
* **Testable Outcome**:
  * Download interrupted mid-transfer via simulated worker halt; resuming continues from the saved bbolt checkpoint without refetching already completed chunks, successfully assembling the final file bit-for-bit.
  * Verified passing via `go test -v -race ./...` and `make test`.
